# The source code of [angelblanco.dev](https://angelblanco.dev)

This is my personal webpage and portfolio that you can use as a boilerplate for a fully
functional Nuxt turborepo deployed to Github Pages with Github Actions and fully open sourced.

## Technologies used

- [Nuxt](https://nuxt.com)
- [Turborepo](https://turbo.build/repo)
- [TypeScript](https://www.typescriptlang.org/)
- [Tailwind CSS](https://tailwindcss.com/)
- [ESLint](https://eslint.org/)
- [Antfu Eslint Config](https://github.com/antfu/eslint-config)
- [Vite](https://vitejs.dev/)
- [Daisy UI](https://daisyui.com/)
- [Playwright](https://playwright.dev/)
- [Storybook](https://storybook.js.org/)

## Nuxt modules

You can find all modules in [apps/angelblanco.dev/nuxt.config.ts](./apps/angelblanco.dev/nuxt.config.ts).

- `@nuxtjs/i18n`: The web page supports internationalization in both Spanish and English.
- `@nuxtjs/color-mode`: Theme management integrated with Daisy UI.
- `@nuxtjs/seo`: Nuxt SEO is configured with all modules in reasonable detail. The `og:image` files are rendered with [Takumi](https://takumi.kane.tw/) while prerendering, so no browser is needed.
- `@nuxt/fonts`: Loads the fonts of [packages/fonts](./packages/fonts/) on the web page and feeds them to the `og:image` renderer.
- `@nuxt/icon`: Icon sets are installed in [apps/angelblanco.dev/package.json](./apps/angelblanco.dev/package.json).
- `@vueuse/nuxt`: Used for click outside and other utilities.
- `@nuxt/content`: For Markdown content management throughout the app.
- `@nuxt/test-utils/module`: For unit and Nuxt testing. For E2E testing, [Playwright](https://playwright.dev/) is used under [packages/playwright](./packages/playwright/).
- `@nuxt/scripts`: Loads cookieless [Cloudflare Web Analytics](https://developers.cloudflare.com/web-analytics/) after hydration when `NUXT_PUBLIC_SCRIPTS_CLOUDFLARE_WEB_ANALYTICS_TOKEN` is set at build time.
- `@nuxt/image`

## Project structure

- `apps`: Deployable applications.
  - `angelblanco.dev`: The source code of the webpage itself, composing the different packages from the Turborepo.
- `packages`: Shared packages for different tools.
  - `conventions`: Guidance for LLM agents.
  - `tsconfig`: Base shared `tsconfig.json` configurations for TypeScript projects.
  - `eslint`: Custom ESLint configuration shared across the monorepo.
  - `fonts`: The fonts as dependencies, the `@nuxt/fonts` configuration and the import that loads them in Storybook.
  - `tailwind`: Tailwind 4 CSS file with Daisy UI integration.
  - `playwright`: E2E tests with different browser integrations.

## Requirements to run

- **Node JS**: The latest Node.js LTS version.
- **pnpm**: The version is pinned in package.json.
- **Operating system**: I only build this repo on Ubuntu, both bare-metal and WSL versions.

## How to install and run this project?

Clone the repo and run:

```bash
pnpm install
```

To run the E2E tests, you need to install the [Playwright](https://playwright.dev/) browsers at least the first time:

```bash
cd packages/playwright
pnpm exec playwright install --with-deps
```

In order to start a dev server, run:

```bash
pnpm dev
```

If you have some trouble after updating, it may help to clean up autogenerated files. You can then run:

```bash
pnpm fresh
```

To browse the components in [Storybook](https://storybook.js.org/), run:

```bash
pnpm storybook
```

It serves on port `6006` in the main checkout (`NUXT_PORT + 3006`, see [the Storybook conventions](./packages/conventions/storybook.md)). To build it as a static site in `apps/angelblanco.dev/storybook-static`, run:

```bash
pnpm build:storybook
```

To prerender the webpage, you need to run:

```bash
pnpm build
```

To build and preview the resulting webpage, run:

```bash
pnpm preview
```

To trigger the E2E tests, run `pnpm preview` and in another terminal, run:

```bash
cd packages/playwright
# If you want to regenerate all screenshots
pnpm run test:e2e:fresh

# If you just want to run the test suite
pnpm run test:e2e
```

The E2E tests will also work if you launch the `pnpm dev` server, however in order to simulate github pages behaviour, `pnpm preview` is preferred.
